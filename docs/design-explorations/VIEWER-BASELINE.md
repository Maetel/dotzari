# Dotzari 학습 화면 기준안

이 문서는 `docs/design-explorations/index.html`에 구현된 학습 화면을 다음 설계와 구현의
시작점으로 삼기 위한 인수인계 문서다. 이 문서와 같은 커밋의 화면이 현재 기준안이며,
이전 탐색 파일은 비교 이력으로만 사용한다. 현재 우선순위는 학습 화면이며, 제작 화면은
이 기준이 안정된 뒤 그 구조를 편집할 수 있도록 맞춘다.

## 1. 현재 결정한 제품 구조

학습 콘텐츠의 계층은 다음과 같다.

```text
강의
└─ 챕터
   └─ 스텝
      ├─ 노드
      └─ 노드 사이의 연결
```

- **강의**는 하나의 설명 주제와 전체 그래프를 가진다.
- **챕터**는 책의 장처럼 의미가 이어지는 여러 스텝을 묶는다.
- **스텝**은 노드가 생성·이동·연결되며 설명이 한 단계 진행되는 단위다.
- **노드**는 텍스트 한 줄이 아니라 코드, 표, 수치, 시각 자료, 인용, 체크리스트,
  접을 수 있는 설명 등 실제 학습 내용을 담는다.
- **연결**은 노드 사이의 의미와 진행 방향을 보여 준다.

현재 샘플은 강의마다 7개 스텝을 3개 챕터로 묶는다.

| 챕터 | 포함 스텝 | 현재 생성 규칙 |
|---|---:|---|
| 1장 | 1~2 | 첫 번째와 두 번째 개념 그룹 |
| 2장 | 3~4 | 세 번째와 네 번째 개념 그룹 |
| 3장 | 5~7 | 다섯 번째와 여섯 번째 개념 그룹, 전체 정리 |

이 2·2·3 구성은 화면을 검증하기 위한 초기값이다. 제품 데이터에서는 챕터가 제목,
요약, 정렬 순서, 소속 스텝을 직접 가져야 하며 스텝 수를 고정하면 안 된다.

## 2. 학습 화면의 정보 구조

모바일 화면은 위에서 아래로 다음 순서다.

1. 강의 제목과 전체 노드 수
2. 챕터와 스텝을 합친 진행 인디케이터
3. 현재 스텝의 핵심 문장과 짧은 설명
4. 현재 스텝까지 나타난 노드 캔버스
5. 선택한 노드의 설명
6. 이전·다음 스텝 이동

첫 화면에서 학습자가 알아야 하는 것은 현재 강의, 현재 챕터, 챕터 안의 위치,
현재 설명과 다음 이동이다. 제작 도구나 내부 데이터는 학습 화면보다 앞에 두지 않는다.

### 챕터·스텝 통합 인디케이터

기존의 독립된 스텝 막대와 챕터 카드를 하나로 합쳤다.

- 상단에는 `현재 챕터`, 챕터 제목, `스텝 1/2`처럼 챕터 내부 위치를 표시한다.
- 아래 막대는 챕터별 영역으로 나뉘며, 영역 너비는 포함된 스텝 수에 비례한다.
- 각 챕터 안의 작은 막대 하나가 한 스텝이다.
- 현재 스텝, 지난 스텝, 아직 보지 않은 스텝을 형태와 색으로 구분한다.
- 작은 스텝 막대를 누르면 해당 스텝으로 이동한다.
- 챕터 이름을 누르면 해당 챕터의 첫 스텝으로 이동한다.
- `전체 보기`를 누르면 챕터 제목, 요약, 진행률을 담은 전체 챕터 목록이 열린다.

캔버스 안에도 챕터별 큰 경계와 제목을 표시한다. 상단 인디케이터는 탐색을,
캔버스 경계는 확대·이동 중 현재 위치 파악을 담당한다.

## 3. 캔버스 동작 기준

캔버스는 한 화면에 모든 노드를 맞추지 않는다. 학습자가 확대·축소하고 이동하면서
전체 설명을 탐색하는 것을 전제로 한다.

- 노드는 절대 좌표 기반의 넓은 월드에 배치한다.
- 스텝이 진행될수록 새 열이 오른쪽에 생기며 흐름도 오른쪽으로 이어진다.
- 노드 수나 내용 길이에 맞춰 화면 비율로 축소하지 않는다.
- 점 배경은 월드에 속하므로 스크롤과 드래그를 따라 함께 움직인다.
- 드래그를 놓은 위치에서 즉시 멈춘다. 스냅이나 추가 관성 이동은 없다.
- 확대 비율은 현재 65%~160%이며 확대·축소·100% 복귀 버튼을 제공한다.
- 두 손가락 확대는 보존하고 빠른 두 번 탭에 의한 화면 확대만 막는다.
- 단계가 바뀌면 현재 단계의 열을 볼 수 있도록 이동하지만, 사용자가 직접 옮긴 뒤에는
  임의의 위치로 끌어당기지 않는다.

연결선은 고정된 선 그림이 아니다. 렌더링된 노드 크기를 측정한 뒤 실제 경계에서
시작하고 끝나도록 다시 계산한다.

## 4. 노드 표현 기준

현재 복잡한 샘플은 강의마다 24개 노드와 30개 이상의 연결을 사용한다. 노드는 다음
형식을 순환해서 사용하며 콘텐츠에 따라 크기가 다르다.

- 요약 설명
- 핵심 수치
- 접을 수 있는 설명
- 시각 자료
- 여러 경로 목록
- 체크리스트
- 표
- 인용문
- 실제 코드

접힌 아코디언은 숨겨진 내용만큼 높이를 줄인다. 펼치면 실제 높이를 다시 측정하고,
같은 열의 아래 노드와 연결선, 챕터 경계를 함께 재배치한다.

코드 노드는 내부 스크롤을 제공하고 캔버스 드래그와 입력을 분리한다. 긴 코드를 노드
높이만 계속 늘려 표시하지 않는다. `크게 보기`를 통해 전용 뷰로 이동한다.

## 5. 긴 콘텐츠 전용 뷰

현재 Node.js 샘플에는 176줄짜리 `server.mjs`를 넣어 긴 코드 동작을 검증한다.
전용 뷰에는 세 가지 시안이 같은 화면의 탭으로 구현되어 있다.

1. **전체 파일**: 파일 전체를 줄 번호와 함께 읽고 가로·세로로 스크롤한다.
2. **설명과 코드**: 위쪽 설명 구간을 선택하면 관련 줄로 이동한다. 모바일에서는
   좌우 분할을 쓰지 않고 코드가 전체 너비를 사용한다.
3. **구조 지도**: 현재 함수 범위, 주요 심볼, 파일 전체 미니맵으로 긴 코드 안의 위치를
   확인한다.

현재 기본 진입은 `전체 파일`이다. 학습 목적에 따라 어느 시안을 기본으로 할지는 아직
확정하지 않았다. 코드 외의 큰 표, 고해상도 이미지, 긴 문서에도 같은 전용 뷰 틀을
확장할 수 있어야 한다.

## 6. 샘플 강의

다섯 강의가 같은 구조와 대표 복잡도를 검증한다.

| ID | 분야 | 설명 |
|---|---|---|
| `runtime-system` | 소프트웨어 | Node.js 요청이 동기 실행, I/O, 대기열, 응답으로 갈라지고 합류한다. |
| `tidal-carbon` | 생태학 | 갯벌의 탄소가 생산자, 먹이망, 분해자, 퇴적층을 순환한다. |
| `urban-flood` | 도시 방재 | 폭우와 배수 병목, 침수, 경보와 대응의 흐름을 설명한다. |
| `exhibition` | 전시 기획 | 연구, 보존, 공간, 콘텐츠 작업이 설치와 운영으로 합류한다. |
| `stellar-life` | 천문학 | 별의 진화가 질량에 따라 갈라지고 물질을 다음 세대로 돌려준다. |

단순한 단어 나열로 샘플을 줄이지 않는다. 실제로 읽고 관계를 학습할 수 있는 내용과
분기, 합류, 예외, 긴 콘텐츠가 있어야 배치와 탐색을 검증할 수 있다.

## 7. 구현 위치와 현재 데이터 구조

기준 구현은 [`index.html`](./index.html) 한 파일에 있다.

- `buildScenario`: 노드 크기, 연결 등장 단계, 챕터를 조립한다.
- `chapterRanges`: 현재 임시 챕터 묶음인 `[0,1]`, `[2,3]`, `[4,5,6]`을 정의한다.
- `chapterNavigationMarkup`: 챕터·스텝 통합 인디케이터와 전체 챕터 목록을 만든다.
- `chapterRegionsMarkup`: 캔버스의 챕터 경계를 만든다.
- `fixedFlowPosition`: 오른쪽으로 이어지는 절대 좌표를 계산한다.
- `layoutComplexNodes`: 실제 노드 높이를 측정해 같은 열과 챕터 경계를 다시 배치한다.
- `bindComplexViewport`: 확대·축소와 드래그를 처리한다.
- `codeViewerMarkup`: 긴 코드 전용 뷰 세 가지를 만든다.

다음 구현에서는 챕터를 자동 계산 결과가 아닌 명시적인 데이터로 옮기는 것이 우선이다.
권장되는 최소 형태는 다음과 같다.

```js
{
  id: 'chapter-1',
  title: '입력과 동기 실행',
  summary: '실행 재료가 모여 동기 실행을 시작합니다.',
  stepIds: ['collect-inputs', 'start-sync-execution']
}
```

스텝도 배열 위치가 아닌 안정적인 ID를 가져야 재정렬, 복제, 링크 공유, 학습 기록 저장을
안전하게 구현할 수 있다.

## 8. 로컬 실행과 상태 재현

```bash
cd docs/design-explorations
node server.mjs
```

그다음 `http://127.0.0.1:4318`을 연다. 학습 화면이 기본이며 다음 주소 매개변수로
상태를 바로 재현할 수 있다.

- `?scenario=tidal-carbon&step=3`: 강의와 스텝 선택. 현재 `step`은 0부터 센다.
- `?role=producer`: 제작 화면 열기
- `?theme=midnight`: 전체 화면 어두운 테마
- `?chapters=open` 또는 `#chapters`: 전체 챕터 목록 열기
- `?codeView=focus` 또는 `#focus`: 전체 파일
- `?codeView=split` 또는 `#split`: 설명과 코드
- `?codeView=map` 또는 `#map`: 구조 지도

저장소 루트에서 `npm test`를 실행하면 현재 자동 테스트 10개를 확인할 수 있다.

## 9. 다음 세션의 우선순위

1. 이 기준 화면을 유지한 채 챕터를 명시적인 데이터 모델로 바꾼다.
2. 챕터 수와 스텝 수가 달라져도 통합 인디케이터가 읽히는지 검증한다.
3. 챕터 제목 수정, 스텝 소속 변경, 순서 변경을 위한 제작 흐름을 설계한다.
4. 큰 이미지·표·문서까지 긴 콘텐츠 전용 뷰를 확장한다.
5. 실제 모바일 Safari와 Android Chrome에서 드래그, 두 손가락 확대, 빠른 두 번 탭,
   코드 내부 스크롤을 다시 확인한다.
6. 안정적인 강의·챕터·스텝 ID와 저장 형식을 정의한다.

## 10. 아직 확정하지 않은 내용

- 챕터 안에 하위 챕터를 허용할지
- 챕터 완료 조건과 학습 진행률 저장 방식
- 스텝 사이를 자유롭게 이동할 수 있는 범위
- 긴 콘텐츠 전용 뷰의 기본 모드
- 제작 화면에서 챕터를 카드, 트리, 타임라인 중 무엇으로 편집할지
- 여러 챕터에서 같은 노드를 공유할 때의 표시와 학습 기록 방식

이 항목들은 현재 화면을 임의로 바꾸기 전에 별도 시안과 실제 콘텐츠로 검증해야 한다.

## 11. 유지해야 할 기준

- 모든 노드를 한 화면에 억지로 맞추지 않는다.
- 캔버스 배경과 콘텐츠의 좌표계를 분리하지 않는다.
- 드래그 종료 뒤 스냅이나 관성으로 위치를 추가 이동시키지 않는다.
- 아코디언이 접혔는데 빈 높이를 남기지 않는다.
- 긴 코드를 노드 높이만 늘려 해결하지 않는다.
- 챕터와 스텝 진행 정보를 서로 다른 영역에 중복해서 보여 주지 않는다.
- 밝은 테마 안에 독립적인 어두운 코드·입력 화면을 남기지 않는다.
- 모바일 두 손가락 확대를 viewport 설정으로 막지 않는다.
- 샘플 데이터를 의미 없는 짧은 문구로 축소하지 않는다.
