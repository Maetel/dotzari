# Dotzari 캔버스 좌표계

이 문서는 캔버스 배치, 이동, 확대·축소를 구현할 때 사용하는 좌표계의 기준입니다.
데스크톱과 모바일은 같은 월드 좌표를 사용하며, 모바일 전용 원점이나 별도의 노드 좌표를
만들지 않습니다.

## 1. 좌표계는 세 단계로 구분합니다

| 좌표계 | 단위와 원점 | 사용하는 값 |
| --- | --- | --- |
| 월드 좌표 | 확대 전 CSS px, 전체 캔버스 왼쪽 위가 `(0, 0)` | 노드 `x`, `y`, `width`, `height`, 챕터 경계, 연결선 |
| 스크롤 좌표 | 확대가 적용된 콘텐츠 px, 스크롤 가능한 콘텐츠 왼쪽 위가 `(0, 0)` | `scrollLeft`, `scrollTop` |
| viewport 좌표 | 실제 화면 px, 보이는 캔버스 영역 왼쪽 위가 `(0, 0)` | `clientWidth`, `clientHeight`, `PointerEvent.clientX/Y`에서 캔버스 rect를 뺀 값 |

페이지 좌표와 상단 메뉴 높이는 캔버스 카메라 계산에 넣지 않습니다. 상단 메뉴를 제외한
실제 캔버스 element의 `clientWidth`와 `clientHeight`가 viewport 크기입니다. iOS safe area도
앱 shell이 처리하며 월드 원점을 바꾸지 않습니다.

## 2. 변환식

월드의 한 점을 viewport에서 표시할 위치는 다음과 같습니다.

```text
viewportX = worldX × zoom − scrollLeft
viewportY = worldY × zoom − scrollTop
```

따라서 월드의 한 점을 viewport의 원하는 위치에 놓는 카메라 값은 다음과 같습니다.

```text
scrollLeft = worldX × zoom − desiredViewportX
scrollTop  = worldY × zoom − desiredViewportY
```

`scrollLeft`와 `scrollTop`은 이미 확대가 반영된 콘텐츠 px입니다. 여기에 zoom을 다시 곱하거나
나누지 않습니다. 반대로 노드 배치값은 월드 좌표이므로 화면 위치를 계산할 때 zoom을 정확히
한 번 적용합니다.

## 3. 모바일 규칙

- 모바일에서도 노드의 절대 월드 좌표와 열 간격을 바꾸지 않습니다.
- 달라지는 값은 실제 캔버스 viewport 크기와 기본 zoom뿐입니다.
- 현재 스텝으로 이동할 때 `스텝 번호 × 열 너비` 같은 추정값을 사용하지 않습니다. 렌더링 후
  측정된 현재 스텝 노드의 왼쪽·오른쪽 경계를 사용합니다.
- 측정된 경계는 `worldBoundsToScrollOffset`으로 변환하고, 가능한 경우 viewport 가로 중앙에
  배치합니다. 월드 시작과 끝에서는 실제 스크롤 범위 안으로 제한합니다.
- 마지막 열도 중앙에 놓을 수 있도록 월드 오른쪽에 viewport 절반만큼의 카메라 여백을 둡니다.
  이 여백은 배경이 이어지는 탐색 공간이며 노드·챕터·연결선의 절대 좌표를 변경하지 않습니다.
- 직접 주소로 스텝에 진입해도 같은 위치가 나와야 합니다. viewport가 연결되고 노드 측정이
  끝난 뒤 최초 카메라를 설정합니다.
- 화면 회전이나 viewport 크기 변경은 `ResizeObserver`로 실제 캔버스 크기를 다시 읽습니다.
  `window.innerWidth`, 문서 폭, 기기 화면 폭을 대신 사용하지 않습니다.

## 4. 드래그와 확대 규칙

- 드래그의 `clientX/Y` 차이는 viewport px이므로 `scrollLeft/Top`에 그대로 더하거나 뺍니다.
  zoom으로 나누거나 곱하지 않습니다.
- 드래그를 놓으면 그 위치에서 즉시 멈춥니다. 스냅, 관성, 지연된 smooth scroll을 실행하지
  않습니다.
- 자동 카메라 이동은 스텝 ID가 실제로 바뀔 때 한 번만 실행합니다. 노드 측정, 아코디언 높이
  변경, 선택, 드래그 뒤에는 다시 중심으로 끌어오지 않습니다.
- 확대 중심의 월드 좌표는 `(scroll + viewportPoint) / oldZoom`으로 구하고, 새 스크롤은
  `worldPoint × newZoom − viewportPoint`로 계산합니다.
- 점 배경은 `.dz-lesson-canvas__world`에 포함합니다. 배경과 노드를 서로 다른 transform으로
  움직이지 않습니다.

## 5. 회귀 방지 검증

다음 상태를 390×844와 430×932에서 확인합니다.

1. 첫 스텝 직접 진입: 첫 열이 월드 시작 안에서 읽히고 가로 넘침이 없습니다.
2. 두 번째 스텝 직접 진입: 현재 스텝 노드 묶음이 가로 중앙에 있으며 이전 열 때문에 밀리지
   않습니다.
3. 다음·이전 이동: 매번 실제 현재 스텝 경계를 기준으로 한 번만 이동합니다.
4. 캔버스 드래그: pointer up 뒤 `scrollLeft/Top`이 더 변하지 않습니다.
5. 확대·축소: 확대 전 중심에 있던 월드 지점이 확대 후에도 같은 viewport 지점에 남습니다.
6. 최종 스텝처럼 새 노드가 없는 단계: 마지막으로 생성된 열을 기준으로 표시합니다.

코어 단위 테스트는 모바일 viewport에서 실제 경계를 중앙에 놓는 계산과 월드 시작점 제한을
검증합니다. 브라우저 검증에서는 노드의 `getBoundingClientRect()`가 viewport 안에서 읽을 수
있는 위치인지 함께 확인합니다.

## 6. 2026-08-03 검증 기록

- 390×844 두 번째 스텝 직접 진입에서 캔버스는 `(0, 58)–(390, 844)`를 사용했고, 현재 스텝
  네 카드의 왼쪽은 `101.84px`, 가장 오른쪽 경계는 `289.04px`였다.
- 같은 크기의 첫 스텝은 `24.04–304.84px`, 최종 스텝의 마지막 열은 `101.04px`에서 시작했다.
- 430×932 두 번째 스텝은 `121.84–309.04px`에 표시됐다.
- 모든 모바일 상태에서 문서 크기와 viewport 크기가 같았고 페이지 scroll은 `0`이었다.
- 캔버스 drag로 `scrollLeft`가 `167 → 287`로 바뀐 뒤 550ms 후에도 `287`을 유지했다.
- 1024×768, 1280×900, 1440×900의 Paper·Midnight에서 페이지 넘침, 캔버스 잘림, 오류
  overlay와 browser runtime error가 없었다.
